Comprendre le backend ISIS Capitalist

Guide actualisé après les corrections du 10 octobre 2026. Le guide complet du projet se trouve dans GUIDE-JEU-FRONTEND-BACKEND.md à la racine ; les raisons des changements sont dans CORRECTIONS-JUSTIFICATIONS.md.

Architecture

Angular → GraphQL → GraphQlResolver → AppService → JSON du joueur

schema.graphql définit le contrat. NestJS génère les classes graphql.ts. origworld.ts contient le modèle initial. Le resolver valide les actions ; le service calcule le temps, les gains, les bonus et les anges.

Une action dans l’ordre

  1. Lire la sauvegarde du joueur.
  2. Actualiser les gains avec l’ancienne quantité et les anciens bonus.
  3. Vérifier que l’action est possible.
  4. Prélever son coût et appliquer son effet.
  5. Sauvegarder et retourner les champs GraphQL demandés.

Temps de production

Les durées sont en millisecondes. timeleft représente toujours le temps restant. Sans manager, un cycle peut se terminer une seule fois. Avec manager, plusieurs cycles peuvent se terminer pendant l’absence.

Si E < R : aucun gain, reste R − E.
Sinon : cycles = 1 + floor((E − R) / D)
         reste = D − ((E − R) modulo D)

Exemple : D = 10 000 ms, R = 2 000 ms, E = 3 000 ms. Un cycle finit et le suivant possède 9 000 ms restantes.

Gains, bonus et reset

gain = cycles × quantité × revenu × (1 + activeangels × angelbonus / 100)
achat = cout × ((croissance^quantité − 1) / (croissance − 1))
anges gagnés = max(0, floor(150 × sqrt(score / 10^15)) − totalangels)

Le bonus de gain multiplie le revenu. Le bonus de vitesse divise la durée et ajuste le temps restant pour conserver l’avancement. Le bonus d’ange ajoute son ratio au pourcentage. Un unlock ne s’applique qu’une fois grâce à unlocked.

Un manager est payé et ne peut pas être acheté deux fois. Le reset reprend le monde initial, conserve le score et ajoute les nouveaux anges au total et aux actifs. Dépenser des anges diminue les actifs, pas le total déjà réclamé.

Sauvegardes et précision

lastupdate est un entier en secondes dans l’API ; lastupdateMs conserve la date exacte dans le JSON, car le type GraphQL Int ne peut pas représenter une date Unix en millisecondes. saveVersion=2 identifie les parties corrigées.

Une ancienne partie garde ses quantités, soldes et achats. Ses durées sont reconstruites depuis les bonus acquis. Ses cycles automatiques reprennent au début d’un cycle ; les gains de l’intervalle ancien ambigu ne sont pas reconstitués. Un JSON illisible provoque une erreur au lieu d’être remplacé.

Vérification

24 tests backend et 23 tests frontend réussis, plus sept scénarios sur l’API réelle. Les tests vérifient les paiements, doublons, cycles courts, bonus, anges et sauvegardes. L’échange avec le serveur d’un autre groupe reste à essayer.
